# Channel + Community SOP

This SOP defines how to maintain a reliable, low-noise, high-trust driver communication system.

## 1) Structure and purpose

### WhatsApp Channel (one-way, official)

Use for:
- Incentive/scheme announcements
- Peak earning windows
- Reactivation campaigns
- Safety advisories (rain, traffic disruption, event spikes)

Do not use for:
- Long discussions
- Individual support resolution

### WhatsApp Community (two-way, support + operations)

Required groups:
1. `Mumbai Announcements` (admin-only)
2. `Driver Helpdesk`
3. `Western Zone Ops`
4. `Central and Harbour Zone Ops`
5. `Navi Mumbai Zone Ops` (optional if scale justifies)

## 2) Role and responsibility matrix

| Role | Core duties | Backup |
|---|---|---|
| Community Lead | Content quality, cadence, metrics, escalation | Operations Manager |
| Helpdesk Agent | Query handling, ticket logging, escalation routing | Helpdesk Agent 2 |
| Zone Captain | Local demand intelligence, onboarding, rumor control | Senior driver captain |
| Moderators | Spam/fraud actions, compliance with rules | Community Lead |

## 3) Posting standards

Every scheme post must include:

- What
- Who (eligibility)
- When (window)
- Where (city/zone)
- How much
- How to unlock (trip target/conditions)
- Support path

### Approved post template

```
OLA Auto Mumbai Update (Official)
Scheme: <bonus details>
Eligibility: <who can earn>
Window: <date/time>
Zones: <zone list>
Target: <trip/rating condition>
Example payout: <sample calculation>
Support: <helpdesk route>
```

## 4) Language policy

- Use simple language in Roman Hindi + Roman Marathi + English.
- Keep each line short and clear.
- Avoid ambiguous financial terms.

## 5) Moderation policy

### Content violations
- Fake incentive information
- Fraud links or payment asks
- Abuse/harassment
- Repeated off-topic spam

### Action framework

1. First offense: warning.
2. Second offense: 24-hour mute or restricted posting.
3. Third offense: removal from group.
4. Fraud/scam attempt: immediate removal + alert broadcast.

## 6) Reactivation workflow

Segments:
- 7-day inactive
- 15-day inactive
- 30+ day inactive

Cadence:
- Max 2 proactive nudges per week unless driver replies.
- Escalate 30+ inactive to assisted callback by support.

## 7) Helpdesk SLA

| Metric | Target |
|---|---|
| First response time (business hours) | <= 2 hours |
| Same-day resolution | >= 70% |
| Escalation tagging accuracy | >= 95% |

Business hours suggestion: 08:00 to 20:00 IST.

## 8) Risk controls

- Keep channel/group links controlled (avoid unrestricted forwarding).
- Rotate invite links every 30 days if abuse detected.
- Pin anti-fraud warning permanently.
- Maintain escalation contacts for urgent payout/app issues.

## 9) Weekly review agenda (30 minutes)

1. Follower/member growth by zone.
2. Post performance: views and reactions.
3. Helpdesk backlog and SLA breaches.
4. Reactivation conversion by cohort.
5. Next week experiments (timing/language/copy variant).
